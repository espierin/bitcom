Data standards

Reliable H&I data exchange starts with a result that is unambiguous, traceable to its nomenclature and meaningful beyond the laboratory that created it.

The purpose

Make the clinical meaning travel with the data

HLA and KIR results are unusually information-dense: a report may contain allele ambiguity, phase, copy-number or locus uncertainty, assay-specific evidence and an interpretation that directly affects donor selection or transplant care. A standard must therefore preserve what is known and what remains unresolved.

BITCom helps translate this need into workable data models, exchange specifications, validation practice and education. The objective is not one universal file format: it is a connected, versioned ecosystem in which laboratories, registries, manufacturers, researchers and clinical systems can interpret data consistently.

Three questions for every exchange
What does the result mean? Which nomenclature and reference release were used? Can the receiving system retain the result without silently changing its meaning?

The standards landscape

Complementary standards for different kinds of information

Genotype grammar

GL String and GLSC

The Genotype List (GL) String is a compact, machine-parseable grammar for HLA and KIR genotypes. Its operators explicitly represent allele lists, phased alleles, genotype ambiguity and multilocus unphased data. The Genotype List String Code (GLSC) adds the gene-family namespace and the relevant nomenclature version or creation date, so a result can be interpreted in its historical context.

Read the GL String specification
Structured genotyping exchange

HML

Histoimmunogenetics Markup Language (HML) is an XML-based exchange format for HLA and KIR genotyping. It can carry typing-method information, allele assignments, consensus sequence and reference-database provenance; GL Strings can be included for a concise representation of the genotype. HML is especially useful where the result must travel together with laboratory and assay context.

Phenotype and antibody interpretation

PL String, PLSC and HAML

Phenotype List (PL) String and its coded form PLSC extend the same disciplined approach to protein- and antigen-level data: assay reagents, test results and clinical antibody interpretations. PL String is designed to express heterodimers and antigen ambiguity. It is intended for use in structured messages, including the developing HLA Antibody Markup Language (HAML), rather than as a replacement for genotype standards.

Read the PL String publication

From a result to an interoperable record

What an implementation should preserve

Meaning and ambiguity

Encode ambiguity and phase explicitly; do not reduce an uncertain genotype or antibody interpretation to a preferred-looking value merely because a downstream system cannot represent the uncertainty.

Provenance and version

Record the namespace, nomenclature/reference-database release or the applicable creation date, the method and the interpretation context. A value without its version is not reproducible.

Validation and conformance

Use published schemas, grammar validators and test data at system boundaries. Validate when data are created, imported, exported and transformed—and retain the original report alongside derived values.

EFI collaboration

BITCom and the EFI Standards Committee

EFI’s Standards Committee owns the European laboratory standards and the process by which these are maintained. BITCom brings the technical and implementation perspective: how structured H&I data are represented, communicated, stored, validated and used in real laboratory and clinical workflows.

The committees should work as a defined partnership. BITCom can identify interoperability needs, evaluate technical options, convene expert input and draft implementable guidance. The Standards Committee determines whether and how requirements enter EFI Standards and coordinates the formal review and approval route.

EFI has reported this collaboration explicitly: BITCom supports data standards and their inclusion in EFI standards guidance, while engaging with the Standards Committee on the appropriate use and communication of immunogenetics data.

Governance principle
Technical material on this page is educational or externally maintained unless it is explicitly labelled as an approved EFI standard. Publication here does not make a draft, a software implementation or an external specification an EFI requirement.

Priority topics

A practical agenda for BITCom

  • Guidance for lossless HLA and KIR result exchange. Map laboratory needs to GL String/GLSC and HML capabilities, including versioning, ambiguity and phase.
  • Antibody data harmonisation. Support the continuing development and real-world testing of HAML and PL String/PLSC use cases, with clear boundaries between raw assay information, analytical result and clinical interpretation.
  • Interoperability with healthcare systems. Follow relevant HL7 FHIR developments so H&I data can be exchanged safely alongside the rest of the clinical record.
  • Conformance, education and adoption. Develop examples, validation approaches and teaching materials with laboratories, software suppliers and the EFI community; do not publish local conventions as universal requirements.
