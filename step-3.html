3.0 Create your variant list (you will reuse it everywhere)

Goal: list each amino-acid difference between your synthetic protein and the closest known allele protein in a clean, consistent format.

What you do

Open synthetic_protein.txt.

Compare it to the closest known allele protein (from BLAST/alignment).

Write down each amino-acid difference in a clean, consistent way.

Copy / Paste / Save

COPY: your synthetic protein sequence (and the closest allele protein sequence or alignment snippet).

WRITE (format): one change per line, e.g., 80 I->T; 116 D->Y; 156 insertion: +G; 233 deletion: ΔK

SAVE: as step3_variant_list.txt

Quick rule

If you have only DNA differences: do not guess. First translate (SFAT/ORFfinder/ExPASy), then list AA changes.

?Help me through this step

Open your saved alignment and a new notes file. Find each mismatch or gap and write one line for it. Include the reference letter, variant letter and position. State which sequence supplies the position numbers.

If you get stuck

Do not count a gap as an amino acid. For an insertion or deletion, record the neighbouring reference residues as well. Keep a note of whether the protein includes its signal peptide.

3.1.1 Stop codon introduced by the variant

Goal: check if the variant introduces an early stop (truncation).

What you do

Open synthetic_protein.txt.

Look for an early stop sign (some tools show '*' as stop) or an unexpectedly short protein.

Cross-check with NCBI ORFfinder (fast sanity check).

Copy / Paste / Save

COPY: synthetic_CDS.txt (preferred) or synthetic_input_sequence.txt (if CDS not available).

PASTE: into ORFfinder and run.

LOOK FOR: the longest ORF; whether it stops much earlier than expected; whether multiple ORFs appear because of early stops.

SAVE: write a 3–5 line conclusion in step3_truncation_check.txt: 'Stop codon present: yes/no' + evidence (protein has */ORF ends at ...).

?Help me through this step

Use the CDS for the ORFfinder check. Paste the sequence, use the standard genetic code and inspect the forward reading frame corresponding to the annotated coding start. Compare its endpoint with the reference.

If you get stuck

If ORFfinder returns an error, use ExPASy on the same CDS and annotated frame. A dash in Compact output marks a stop. Record the number of translated residues before the first stop and the frame used.

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.

!Understand what you are doing

The longest ORF can start downstream of the biological start. Examine the annotated coding frame as well as the longest result. Introns in genomic DNA can introduce apparent stops, so a genomic translation needs exon context.

3.1.2 Frameshift (insertion/deletion not divisible by 3)

Goal: check whether an indel causes a frameshift and therefore likely truncation.

What you do

From your coding alignment, identify insertions/deletions in the coding sequence.

Check the length: 3, 6, 9... bases -> in-frame; 1, 2, 4, 5... bases -> frameshift.

Confirm with ORFfinder: a frameshift often creates a short, abnormal ORF.

Copy / Paste / Save

COPY: the exact indel from your alignment (length and position).

WRITE: in step3_truncation_check.txt add: 'Frameshift: yes/no', 'Indel length: ... bp', 'Expected consequence: early stop likely / not likely'.

?Help me through this step

Inspect a coding DNA alignment and find each inserted or deleted stretch. Count the bases in the stretch, record its position, and divide the length by three. A remainder indicates a shift in the downstream codon grouping.

If you get stuck

For the supplied case with separate genomic and CDS records, follow the note on Downloads about analysing independent inputs. Confirm the effect by translating the relevant CDS in its annotated frame.

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.

!Understand what you are doing

An insertion or deletion divisible by three preserves the downstream reading frame but can still change the protein. A frameshift changes how downstream bases are grouped into codons and may create an early stop.

3.1.3 Alternative splicing / splice site disruption (genomic sequences)

This only applies if your synthetic sequence includes introns (genomic input).

What you do (simple, manual but effective)

Run SFAT on the genomic sequence and record exon boundaries.

Check whether your variant sits at an exon boundary:

- Donor site (start of intron): usually GT right after the exon

- Acceptor site (end of intron): usually AG right before the next exon

If your variant changes those canonical bases, splicing disruption is plausible.

Optional (stronger): SpliceAI Lookup

If you can express your change as a variant on a reference genome coordinate, use SpliceAI Lookup and record the delta score.

Copy / Paste / Save

WRITE: in step3_truncation_check.txt add: 'Splice-site hit: yes/no', 'Which boundary: exon X donor/acceptor', 'Reason: canonical GT/AG changed / nearby splice motif changed'.

OPTIONAL: add 'SpliceAI delta score' if used.

?Help me through this step

Use the genomic sequence and the exon coordinates from SFAT. For an acceptor, inspect the two intronic bases immediately before the exon starts. For a donor, inspect the two bases immediately after the exon ends.

If you get stuck

Record the exon number, genomic position, reference bases and variant bases. If the sequence starts or ends inside an exon, the relevant boundary may be missing. Record that limitation.

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.

!Understand what you are doing

Canonical GT and AG motifs support recognition of splice boundaries. A changed motif raises a splice hypothesis. The actual RNA product needs additional evidence. SpliceAI lookup also requires a correctly mapped genome coordinate and reference assembly.

Write down what you observed, then explain how it supports your interpretation. For a worked case answer, open the matching case on the Downloads page and expand its Detailed answer.

3.2 Does this change the Antigen Recognition Domain (ARD; and therefore G/P grouping logic)?

ARD definition used here

Class I: peptide-binding domain is encoded by exons 2 and 3.

Class II: peptide-binding domain is encoded by exon 2.

?Help me through this step

3.2.1 Does this lead to another G-group characterization?

Goal: determine whether the ARD nucleotide sequence differs from the closest allele (relative G-group statement).

What you do

Using SFAT output, isolate the ARD nucleotide sequence:

- Class I: exon 2 + exon 3

- Class II: exon 2

Compare that ARD nucleotide sequence to the closest allele’s ARD nucleotide sequence (IPD alignment tool can show exon-level alignments).

If any nucleotide differs in the ARD region, it is not the same G-group as the closest allele (relative statement).

Copy / Paste / Save

COPY: ARD exon nucleotide sequence(s) from SFAT + closest allele ARD exon sequence(s).

COMPARE: identical yes/no.

SAVE: in step3_ard_check.txt write: 'ARD nucleotide change: yes/no' and 'Same G-group as closest allele? yes/no (relative)'.

?Help me through this step

Use the SFAT boundaries or the IPD alignment view to extract the appropriate exons from both alleles. Compare the same exon interval and record substitutions or gaps.

If you get stuck

Keep the exon labels and coordinates alongside the copied sequence. Do not compare an entire genomic record with a spliced exon record.

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.

!Understand what you are doing

A synonymous nucleotide difference may preserve the amino-acid sequence while changing the G-group comparison. Official group membership is assigned in the database, so describe a new exercise sequence in relative terms.

3.2.2 Does this lead to another P-group characterization?

Goal: determine whether the ARD protein sequence differs from the closest allele (relative P-group statement).

What you do

Translate the ARD region (or use your protein alignment) and check whether any AA in the ARD differs.

Any ARD amino-acid difference vs closest allele implies a different P-group (relative statement).

Copy / Paste / Save

COPY: your ARD AA changes from step3_variant_list.txt.

DECIDE: are any within ARD? (Class I: exons 2+3; Class II: exon 2).

SAVE: in step3_ard_check.txt write: 'ARD protein change: yes/no' and 'Same P-group as closest allele? yes/no (relative)'.

?Help me through this step

Use your full protein alignment and exon annotation to identify amino acids in the ARD. Check whether the differences fall in that region and record your relative P-group interpretation.

If you get stuck

An exon can begin partway through a codon. Use the correctly translated full CDS to identify protein changes. Translating an extracted exon from its first base without checking phase can shift the frame.

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.

!Understand what you are doing

Identical ARD protein sequence can coexist with differences elsewhere in the protein. Expression and the documented status of a null allele require separate attention.

3.2.3 Does this alter the peptide repertoire (binding groove)?

You do not prove this here — you flag plausibility.

What you do (workshop rule)

If the change is in ARD, it may affect peptide repertoire.

Strengthen your conclusion using structure (Step 3.3 + optional PyMOL): if the mutated residue points into the binding groove or sits close to the peptide, plausibility increases.

Copy / Paste / Save

WRITE: in step3_ard_check.txt: 'Peptide repertoire impact plausible: low / medium / high'.

WRITE: reason: 'ARD change yes/no; residue points to groove yes/no'.

?Help me through this step

If you get stuck

3.3.2 Identify exposure characteristics of the new amino acids

Goal: map each AA change to exposure (exposed/buried) using NetSurfP output.

What you do

For each line in step3_variant_list.txt, look up the same position in the NetSurfP output.

Record whether it looks exposed or buried (use RSA as your guide).

Copy / Paste / Save

SAVE: in step3_surface_check.txt create one block per variant:

- Position + AA change

- RSA (from NetSurfP)

- Call: exposed / partly exposed / buried

- 1-line interpretation: 'Accessible change yes/no'

?Help me through this step

Open the per-residue output or CSV. Find the position in your full input protein and check that the amino-acid letter agrees with your variant list. Copy the position, letter and RSA into your notes.

If you get stuck

3.3.4 Could this lead to antibody recognition in general?

Goal: do a useful screen without overclaiming specific antibody specificities.

What you do (workshop-level decision rule)

If a residue is surface-accessible (NetSurfP) and different from the closest allele, it can be part of an antibody epitope.

Optional stronger check: see if the position overlaps a known eplet in the HLA Eplet Registry.

Copy / Paste / Save

COPY: variant positions that are 'exposed' from NetSurfP mapping.

OPTIONAL CHECK: look up those positions in the HLA Eplet Registry.

SAVE: in step3_surface_check.txt add: 'Antibody-relevant variants (exposed): [list]', 'Eplet overlap: yes/no/unknown', 'Overall antibody recognition plausibility: low/medium/high'.

?Help me through this step

List the changed residues you judged exposed. If using the Eplet Registry, search with the appropriate HLA context and check that its residue numbering matches yours.

If you get stuck

Keep the output file named in the instructions and note any setting or fallback you used. You can reopen this help while working in another browser tab.
