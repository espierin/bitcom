!Understand what you are doing

3.1.1 Stop codon introduced by the variant

Goal: check if the variant introduces an early stop (truncation).

What you do

Open synthetic_protein.txt from task 2.3 if a protein was established. For an unresolved case, record that status and use the HLA-B demonstration only for practice.

Use the first stop you recorded from the full translation in task 2.3. Check that it precedes the expected reference end in the verified coding frame. A dash in ExPASy Compact output or an asterisk in other translations can mark a stop. Your letters-only protein file gives the amino acids preceding the recorded stop.

For a cross-check, open NCBI ORFfinder. Use the CDS in Enter Query Sequence, standard genetic code and a minimum ORF length of 30 nt for the short workshop examples. If the verified CDS starts with ATG, choose ATG only. Click Submit, then inspect the ORF in the expected strand and frame. Compare its start and stop with the full-CDS translation. If the ORF table does not load or the expected frame is absent, retain the verified full-CDS translation and record why this cross-check was inconclusive.

Copy / Paste / Save

COPY: synthetic_CDS.txt (preferred) or synthetic_input_sequence.txt (if CDS is not available).

PASTE: into NCBI ORFfinder and run.

LOOK FOR: the ORF in the expected coding frame and orientation. Compare its first stop with the reference.

SAVE: write a conclusion of three to five lines in step3_truncation_check.txt: 'Stop codon present: yes/no' + evidence (protein has */ORF ends at ...). Coding integrity ↗

In My workbook: Stop-codon evidence ↗.

?Help me through this step

Work through it

  1. Open the annotated translation and identify the start, frame and first stop. Compare against the same-locus reference in the corresponding frame. Note the codon number and the number of amino acids before the stop.
  2. In NCBI ORFfinder, paste the verified CDS, use the standard genetic code and inspect the ORF with the expected orientation, start and frame. Use its translation and coordinates as a cross-check. If the short ORF is missing, review minimum length and start-codon settings, or translate the annotated frame directly in ExPASy.

Check your result or recover

Record the first stop codon and its CDS interval, the predicted length and the reference comparison. If only genomic DNA is available, note that ORFfinder does not splice introns. Record ‘CDS unresolved’ if no justified coding sequence is available.

!Understand what you are doing

What the result means

An ORF can start downstream or occur on another strand. Its length alone does not tell you that it is the expected HLA coding region.

How to interpret it

A terminal stop at the expected end is normal. A premature stop removes the remaining translated sequence in that frame. Expression and transcript degradation require separate evidence.

3.1.2 Frameshift (insertion/deletion not divisible by 3)

Goal: check whether an indel causes a frameshift and therefore likely truncation.

What you do

Generate a CDS-to-CDS alignment. At each coding indel, count the bases on the row opposite the gap and record the exact length.

Check whether the indel length is divisible by 3. A multiple of 3 preserves the downstream frame. Other lengths shift it. Check the translated frame and first stop to determine the effect.

Cross-check the annotated CDS frame with ORFfinder or ExPASy Translate. A frameshift can create an earlier stop, a later stop, or a new tail.

Copy / Paste / Save

COPY: the exact indel from your alignment (length and position).

WRITE: in step3_truncation_check.txt add: 'Frameshift: yes/no', 'Indel length: ... bp', 'Expected consequence: early stop likely / not likely'. Coding integrity ↗

In My workbook: Frameshift evidence ↗.

?Help me through this step

Work through it

  1. Compare the synthetic and reference CDS at the nucleotide level. Find the first insertion or deletion and copy its flanking bases and coordinates. Count the length of each contiguous coding indel in bases.
  2. Divide the indel length by three. A remainder of one or two shifts the frame at that point. Translate the annotated frame across the change and inspect where the new tail ends. If a later indel restores the frame, document both changes.

Check your result or recover

In your workbook record the coding position, insertion or deletion, length, frame consequence and first stop if present. If all you have is a protein gap, use it as a clue and check the coding DNA before assigning a cause.

!Understand what you are doing

What the result means

Codons are read in triplets. A three-base deletion can remove an amino acid while preserving the downstream frame. A one-base insertion can alter many downstream amino acids.

How to interpret it

A gap in intronic DNA does not directly count toward a coding frameshift. A change to splicing can instead change the set of bases included in the CDS.

3.1.3 Alternative splicing / splice site disruption (genomic sequences)

This only applies if your synthetic sequence includes introns (genomic input).

What you do (simple, manual but effective)

Run SFAT on the genomic sequence and record exon boundaries.

Use the genomic alignment to map the reference boundary onto the variant. Use genomic Start and Length from SFAT to find the last base of the upstream exon (Start + Length minus 1) or first base of the next exon. Inspect the two intronic bases immediately next to the relevant boundary.

- Donor site (start of intron): usually GT right after the exon

- Acceptor site (end of intron): usually AG right before the next exon

If your variant changes those canonical bases, splicing disruption is plausible.

Optional (stronger): SpliceAI Lookup

If you can express your change as a variant on a reference genome coordinate, use SpliceAI Lookup and record the delta score.

Copy / Paste / Save

WRITE: in step3_truncation_check.txt add: 'Splice-site hit: yes/no', 'Which boundary: exon X donor/acceptor', 'Reason: canonical GT/AG changed / nearby splice motif changed'. Coding integrity ↗

OPTIONAL: add 'SpliceAI delta score' if used. Coding integrity ↗

In My workbook: Splice-site evidence ↗.

?Help me through this step

Work through it

  1. Use the genomic input and reference annotation. Locate the exon before and after the suspected boundary. In the coding-strand orientation, read the first two intronic bases after an exon (donor) or the last two before the next exon (acceptor).
  2. Compare the variant and reference over the same boundary, showing a few bases on both sides. Record the exon number, donor or acceptor, genomic input coordinate, reference and variant bases and any SFAT warning. For CDS-only data, write ‘genomic boundary unavailable’.

Check your result or recover

If using SpliceAI Lookup, use a confirmed reference assembly, genomic coordinate and REF/ALT orientation. Workshop FASTA positions are local to the record. If you cannot map reliably or the synthetic change is unavailable, leave the optional score blank.

!Understand what you are doing

What the result means

GT and AG are common canonical donor and acceptor motifs in the coding-strand orientation. Their disruption supports a splice hypothesis. The transcript might use a different site, skip an exon or retain an intron.

How to interpret it

SFAT annotations and splice scores are computational evidence. If the transcript is unknown, give that as the result and carry uncertainty to the protein and immune-recognition tasks.

3.2 Does this change the Antigen Recognition Domain (ARD; and therefore G/P grouping logic)?

ARD definition used here

Class I: peptide-binding domain is encoded by exons 2 and 3.

Class II: peptide-binding domain is encoded by exon 2.

In My workbook: ARD and G/P comparison ↗.

?Help me through this step

Work through it

  1. Determine the locus and class of your comparator. For the HLA-A cases use coding exons 2 and 3. For a class II exercise use exon 2. Find the relevant feature boundaries in both records.
  2. Make separate workbook lines for ‘ARD DNA comparison’ and ‘ARD protein comparison’. Record which exons and positions were covered. If a boundary is missing or the product is unresolved, mark the affected comparison uncertain.

Check your result or recover

!Understand what you are doing

What the result means

The ARD is the peptide-binding domain used in this exercise. The class I α1 and α2 domains form the groove, while the α3 domain lies outside this exon-defined region.

How to interpret it

A change outside the ARD can still affect expression, stability or an exposed surface. ARD identity addresses a narrower question about the peptide-binding domain.

3.2.1 Does this lead to another G-group characterization?

Goal: determine whether the ARD nucleotide sequence differs from the closest allele (relative G-group statement).

What you do

Use the CDS feature table in SFAT for each record. From the sequence below it, copy the bases from each exon’s Start through Start + Length minus 1, inclusive.

- Class I: exon 2 + exon 3

- Class II: exon 2

Compare that ARD nucleotide sequence to the closest allele’s ARD nucleotide sequence (the IPD alignment tool can show exon-level alignments).

If any nucleotide differs in the ARD region, it is not the same G-group as the closest allele (relative statement).

Copy / Paste / Save

COPY: ARD exon nucleotide sequence(s) from SFAT + closest allele ARD exon sequence(s).

COMPARE: identical yes/no.

SAVE: in step3_ard_check.txt write: 'ARD nucleotide change: yes/no' and 'Same G-group as closest allele? yes/no (relative)'. ARD and G/P comparison ↗

In My workbook: ARD nucleotide comparison and G-group evidence ↗.

?Help me through this step

Work through it

  1. Use SFAT or the IPD alignment to identify the reference coding exon boundaries. For a synthetic sequence, compare your SFAT-derived coding exons directly against those reference exons. Keep the exons in order and check coverage.
  2. Inspect each comparable column for a nucleotide substitution or indel. Record the exact difference and exon. If full ARD coding coverage is available, state whether the two ARD nucleotide sequences are identical.

Check your result or recover

If available coverage is partial or the transcript is uncertain, record that scope. Use the IPD grouping documentation for official definitions and check published membership separately for named alleles.

!Understand what you are doing

What the result means

G grouping compares the nucleotide sequence of the peptide-binding exons. A synonymous substitution can change this comparison even when the encoded amino acids are identical.

How to interpret it

Complete ARD nucleotide identity supports a relative same-G statement for the compared sequences. The workshop comparison does not assign an official group name to a synthetic allele.

3.2.2 Does this lead to another P-group characterization?

Goal: determine whether the ARD protein sequence differs from the closest allele (relative P-group statement).

What you do

Use the verified full-CDS translation and protein alignment. Map the ARD exon boundaries into that translation, accounting for the annotated coding frame and boundary-spanning codons. Compare the corresponding amino acids in the aligned rows.

An amino-acid difference in the comparable peptide-binding domain supports a relative difference. Check published P-group membership and expression status separately.

In My workbook: ARD protein comparison and P-group evidence ↗.

?Help me through this step

Work through it

  1. Map the coding exon positions onto your verified protein alignment. Use the full annotated CDS frame to locate boundary-spanning codons. Check the residue letters in the comparable ARD span and record substitutions or indels.
  2. Record ‘ARD amino-acid identity’ separately from ‘official P-group membership’. For a valid full-length ARD comparison, write whether the two ARD amino-acid sequences match. For known alleles, check current IPD P-group tables and record the release.

Check your result or recover

If a stop truncates the ARD, or expression is null or unresolved, report what the sequence comparison actually supports and check the official record before making a membership claim.

!Understand what you are doing

What the result means

P grouping compares the encoded peptide-binding domain amino-acid sequence. Synonymous coding changes can distinguish nucleotide sequences without distinguishing the ARD proteins.

How to interpret it

Expression status matters when interpreting published P-group membership. A hypothetical translation can show amino-acid identity without demonstrating a normally expressed protein.

!Understand what you are doing

What the result means

A residue near the peptide can affect binding directly. Changes farther away can affect structure or stability indirectly. One bound peptide in one structure represents a single observed complex.

How to interpret it

This exercise develops a hypothesis about peptide repertoire. Demonstrating a repertoire shift requires binding or peptide presentation evidence beyond this mapping.

!Understand what you are doing

What the result means
