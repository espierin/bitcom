2.1 Clean the synthetic DNA sequence and save it

Goal: you start with a provided synthetic DNA sequence. Before analysis, make sure it contains only DNA letters (A/C/G/T) and nothing else.

What you do

Copy a synthetic DNA sequence from the workshop materials (GitHub).

Open Notepad (or similar) and paste the sequence.

Clean the sequence: remove the FASTA header and layout characters such as whitespace and line numbers. Check unexpected sequence symbols with the facilitator.

Keep only A/C/G/T.

Save the cleaned sequence as synthetic_input_sequence.txt.

Copy / Paste / Save

COPY: the full synthetic DNA sequence from the workshop materials.

PASTE: into Notepad (scratchpad).

CLEAN: remove header and layout characters. Check unexpected sequence symbols before proceeding.

SAVE: as synthetic_input_sequence.txt

What you have now

One clean DNA sequence (A/C/G/T only) that you can safely paste into web tools.

?Help me through this step

Work through it

  1. Open Downloads and use the case assigned by your facilitator. Choose genomic DNA for the main genomic workflow. If assigned a CDS exercise, record that explicitly and keep it in a separate working file from any genomic entry.
  2. Open the FASTA in a plain-text editor. Keep the original file. Copy from the first sequence line to the last sequence line of that entry. Remove the header, spaces and line numbers from your working copy and save as synthetic_input_sequence.txt.

Check your result or recover

Check the full length against the original after ignoring formatting. If an unexpected symbol appears, locate it in the original and ask before editing. Deleting a nucleotide can change a reading frame or shift every later coordinate.

!Understand what you are doing

What the result means

Genomic and CDS inputs can represent different exercises even under the same case number. A protein file has amino-acid letters and is for the later comparison. Use the file label and source rather than inferring sequence type from a few letters.

How to interpret it

This task prepares an input, not a result. Record the case, file name, type and length so you can reproduce the annotation and BLAST searches.

2.2 Convert synthetic DNA to exons/CDS (and often protein) with SFAT

Goal: analyse the synthetic DNA with SFAT so you can identify exon/intron features (if present), generate the CDS (exons stitched together), and obtain a correct protein sequence.

Tool to use

IPD-IMGT/HLA Sequence Feature Annotation Tool (SFAT).

What you do (click-by-click)

Open the Sequence Feature Annotation Tool page.

Paste your genomic DNA letters only (no FASTA header, no spaces).

Select the locus that matches your sequence (e.g., A, B, DRB1, MICB, etc.).

Select Level: Genomic for a genomic file with introns, or CDS for an assigned coding-only file.

Run the annotation by pressing the “Annotate Sequence Now” button.

Copy / Paste / Save

COPY: the full content of synthetic_input_sequence.txt

PASTE: into SFAT (letters only; no header).

SELECT: locus + correct Level (Genomic or CDS).

SAVE: copy CDS output into synthetic_CDS.txt

SAVE: if SFAT provides translation output, copy protein into synthetic_protein.txt

WRITE DOWN: locus selected + level selected + codon_start (if shown) in closest_match_notes.txt

What to look for in the results

Exon/intron boundaries (where each exon starts/ends in your input). Note: splice changes can introduce premature stops and cause null alleles.

A coding sequence: exonic sequence stitched together (introns removed).

A codon_start / reading-frame hint (important for correct translation).

The translated protein sequence.

?Help me through this step

Work through it

  1. Paste synthetic_input_sequence.txt into SFAT. For a workshop HLA-A input select locus A. Set Level to Genomic for the genomic file or CDS for an assigned coding file. Submit once and leave the results tab open.
  2. Copy the CDS into synthetic_CDS.txt and any translated protein into synthetic_protein.txt. In the workbook record the submitted type, codon_start if shown, exon boundaries if available and any warning. If the input is already CDS, keep the original independent record and compare it with what SFAT returns.

Check your result or recover

If SFAT supplies an apparently normal CDS despite a boundary warning, keep both observations. If no justified CDS is available, record that limitation and consult the facilitator. Use a supplied CDS as a fallback only when its relationship to this exact input is established.

!Understand what you are doing

What the result means

SFAT predicts the expected feature layout from sequence similarity. A splice-site change may disrupt that layout biologically even when the tool reports the usual exon boundaries.

How to interpret it

Keeping the source sequence, settings and warnings separates an observed DNA change from a hypothetical protein. That distinction determines whether the alignment and accessibility tasks can be interpreted for the case.

2.3 Translate the CDS into protein (if not provided by SFAT)

Goal: ensure you end Step 2 with a correct one-letter amino-acid sequence so you can run protein-level comparisons.

Option A (preferred): take the protein directly from SFAT output

In the SFAT results, find the Protein section.

Copy the one-letter amino-acid sequence into synthetic_protein.txt.

Copy / Paste / Save

COPY: the one-letter amino-acid sequence from the SFAT translation output.

SAVE: as synthetic_protein.txt

Option B (manual/universal): translate the CDS with ExPASy Translate

Open ExPASy Translate.

Paste the CDS (from synthetic_CDS.txt) — not the genomic DNA.

Choose an output format (compact/continuous sequence).

ExPASy shows 6 possible frames (3 forward, 3 reverse).

If SFAT provides codon_start, use it to pick the correct forward frame: start=1 (in SFAT) -> frame 1 (in ExPASy); start=2 (in SFAT) -> frame 2 (in ExPASy); start=3 (SFAT)-> frame 3 (in ExPASy).

Copy the protein sequence into synthetic_protein.txt.

Optional: download all frames as a text file.

Copy / Paste / Save

COPY: the full content of synthetic_CDS.txt

PASTE: into ExPASy Translate.

CHOOSE: the correct frame (use SFAT codon_start).

SAVE: as synthetic_protein.txt

?Help me through this step

Work through it

  1. Start from the annotated synthetic CDS or the verified SFAT protein. If using SFAT’s protein, copy the translation itself and record its length. If using ExPASy, paste CDS, select a compact output and run Translate.
  2. Select the annotated coding frame, using codon_start when supplied. Compare with the matching reference start and length, then record the first stop and the amino acids preceding it. Save the supported sequence to synthetic_protein.txt and keep the full translation output as evidence.

Check your result or recover

If you see a short product, compare its CDS codons to the reference before assuming an input error. For an unresolved splice outcome, write ‘protein product unresolved’ and use a facilitator-approved reference example for the later tool practice. Label that example separately.

!Understand what you are doing

What the result means

A correct reading frame can contain an early stop after an indel or a substitution. The other five frames are alternative readings of the same DNA and are not alternative evidence of expression.

How to interpret it

A translated sequence is a prediction from the input and frame. Neither a full-length nor a short in-silico translation establishes expression, protein stability or surface presentation.

2.4 Find the closest known allele (NIH BLAST)

Goal: determine which known allele your synthetic sequence most closely resembles, and document why it looks novel relative to that closest match (identity, coverage, mismatches).

Preferred tools to use

Basic Local Alignment Search Tool: https://blast.ncbi.nlm.nih.gov/Blast.cgi

Alternative for HLA: There are lots of different BLAST services out there to use, but these may or may not have the same library of sequences to compare against or give the same results. Why not repeat the step above using the service at the EBI, https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast? How do the results differ, why might this be?

For DNA sequences: Nucleotide -> Nucleotide BLAST

For protein sequences: Protein BLAST

What you do (Nucleotide similarity)

Go to the BLAST website: https://blast.ncbi.nlm.nih.gov/Blast.cgi (https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast/nucleotide)

Your sequence contains DNA sequences, thus select the option: Nucleotide BLAST nucleotide -> nucleotide

Enter your Query Sequence in the text box.

Press the blue BLAST button on the lower left of the page and wait.

Open Descriptions for the hit list and Alignments to inspect the matching regions. Check the active sort order, query coverage and percent identity.

Choose a same-locus comparator with adequate coverage of the region you will analyse. Document ties and check the actual alignment before deciding.

You can inspect the homology in an alignment by clicking on the description.

Use a complete CDS hit for a coding comparison when it covers the relevant sequence. For a genomic comparison, inspect genomic hits for coverage of introns and splice boundaries.

Identical nucleotides are connected by a “|” between your query sequence and the obtained homologous subject. For mismatches, this symbol is missing.

Copy / Paste / Save

COPY: sequence from the appropriate file (genomic).

PASTE: into the matching NIH BLAST page.

RUN: keep defaults unless instructed otherwise.

SAVE: in closest_match_notes.txt record the top 3 hits for each run: allele name, % identity, alignment length/coverage, mismatches/gaps.

WRITE: 1–2 sentences: closest known allele + evidence + novelty evidence (differences at ...).

?Help me through this step

Work through it

  1. Open Nucleotide BLAST. Paste your genomic query, or record that you are running a separate CDS query. Check the selected database and run. If using EBI or protein BLAST for comparison, record its database and input type separately.
  2. Read the Descriptions and Alignments tabs. Record the top three relevant HLA hits, accession or allele, percent identity, query coverage, aligned length, mismatches and gaps. Open each alignment and inspect the coordinates, orientation and actual differences. Record ties and prefer a same-locus comparator that covers your region of interest.

Check your result or recover

If a hit has 100% identity over a small region, inspect longer hits before choosing. If your genomic query aligns only to CDS, introns may be missing from that comparison. If no suitable hit or the service fails, use the facilitator’s designated comparator and record why it was used.

!Understand what you are doing

What the result means

BLAST reports local similarity. The first row reflects the selected database, scoring and sort order. A high identity applies to the aligned segment, while coverage tells you how much of the query was represented.

How to interpret it

A difference from your chosen comparator is evidence for this exercise. Establishing novelty would require a broader database and sequence validation. Two services can legitimately return different hits.

2.5 Prepare the closest matched allele protein for alignment

Goal: retrieve the protein sequence of the closest matched allele (the reference) from the ANHIG/IMGTHLA GitHub repository, and save it as a single FASTA entry.

What to do

Open the ANHIG/IMGTHLA repository in your browser.

Open the folder: fasta/

Open the protein file for your locus: X_prot.fasta (where X is the gene/locus, e.g., A_prot.fasta, DRB1_prot.fasta, MICB_prot.fasta). View the raw data file.

Find your closest matched allele entry in the file (use Ctrl+F).

Copy the entire FASTA entry: the header line starting with '>' AND the amino-acid sequence lines below it.

Copy / Paste / Save

COPY: Copy the full FASTA entry for the closest matched allele from X_prot.fasta (including the '>' header).

PASTE: Paste into Notepad/TextEdit as your scratchpad.

CHECK: You should see exactly one header line starting with '>' followed by only amino-acid letters (no numbers, no spaces).

SAVE: Save as reference_protein.fasta

What you have now

• A reference protein sequence for the closest matched allele, stored as FASTA (header + sequence) file.

?Help me through this step

Work through it

  1. Use the allele and locus you recorded in 2.4. In ANHIG/IMGTHLA open fasta and the locus-specific _prot.fasta file. Choose Raw and search for the allele name. Check the entire designation on the header, including any expression suffix.
  2. Copy that header and all of its sequence lines through the line before the next >. Save as reference_protein.fasta. Reopen it and check that you have exactly one header, amino-acid letters, and the expected sequence boundaries.

Check your result or recover

If the selected hit is a partial record or lacks a protein entry, ask for the closest usable comparator. Record the accession, allele, coverage and why you chose it. Check that both protein inputs represent the same locus and that you know whether both include the leader.

!Understand what you are doing

What the result means

The BLAST hit identifies a database record. The matching protein FASTA is a separate file and is the actual input to the alignment. A truncated database record can introduce a terminal gap unrelated to your variant.

How to interpret it

Two alleles can encode identical proteins while differing at nucleotide level. A shared protein sequence does not establish G-group identity or the expression status of either allele.

2.6 Convert your SFAT protein output into FASTA format

Goal: your SFAT protein file often contains only the amino-acid letters. Prepare a named FASTA entry for alignment with SMS2 or UniProt by adding a header line and saving the file.

What to do

Open synthetic_protein.txt (your protein sequence from SFAT).

Create a new text file in Notepad/TextEdit.

Add a FASTA header line on the first line, starting with '>' (example: >synthetic_novel_allele).

Paste your protein sequence on the next lines (letters only; line wrapping is optional).

Save as synthetic_protein.fasta

Copy / Paste / Save

COPY: Copy the amino-acid letters from synthetic_protein.txt

PASTE: Paste into a new file under a header line like: >synthetic_novel_allele

CHECK: The file must contain two things only: one '>' header line and amino-acid letters (no '*', no spaces).

SAVE: Save as synthetic_protein.fasta

What you have now

• A FASTA-formatted protein entry for your synthetic allele.

?Help me through this step

Work through it

  1. Open synthetic_protein.txt and a new plain-text file. Type a unique header such as >synthetic_case, press Enter, and paste the verified amino-acid sequence on the next line. Save as synthetic_protein.fasta.
  2. Check that the header begins with > and that the body has letters only. Keep a record of the original length. For a confirmed stop, submit the translated segment before the stop and document that choice. For an X or another unusual letter, read the alignment input guidance before submitting.

Check your result or recover

If Windows saves synthetic_protein.fasta.txt, turn on file extensions or resave with All files. If your current protein is undefined, record the limitation and use a labelled example for the alignment workflow, keeping it separate from your case notes.

!Understand what you are doing

What the result means

FASTA is a packaging format. Adding a header preserves the underlying protein sequence. Keep an untouched source copy and a separate prepared input so you can trace every modification.

How to interpret it

A stop marker is different from an amino acid. Deleting an internal unknown residue can shift all later positions. Record how you handled non-standard symbols before interpreting any residue number.

2.7 Align the two proteins (SMS2 first choice)

Goal: generate a protein alignment between your synthetic allele protein and the closest matched allele protein, so you can see the exact amino-acid differences in context.

Option 1 — SMS2 Pairwise Align Protein (recommended)

Follow the SMS2 instructions, help and screen examples

  1. Check your protein symbols and lengths first. SMS2 can silently remove X and other unsupported characters; follow the linked preparation guidance before proceeding.
  2. Open Pairwise Align Protein ↗. Replace the first example with your reference FASTA and the second with your synthetic FASTA: one entry in each box.
  3. Use BLOSUM62, gap opening 12 and extension 2, then click Submit.
  4. Verify the reported names and lengths. Copy only the two aligned FASTA entries, preserving gaps.
  5. Follow the guide to display the alignment with Color Align Conservation and determine the residue differences.
  6. Save the alignment, settings and observations in your workbook. Use these results for Step 3; you do not need to repeat the alignment with UniProt.

SMS2 calculates in your own browser, avoiding the shared EBI queue. If it cannot handle your input, consult the facilitator; do not silently remove unknown residues.

Option 2 — UniProt Align (original instructions)

Use this second option if requested by the facilitator. It uses the EBI service and may queue. The instructions below apply specifically to UniProt, including its single input box and output filename.

What to do (click-by-click)

Open the UniProt Align tool in your browser.

In the sequence input box, paste BOTH FASTA entries, one after the other:

First: your synthetic protein FASTA (synthetic_protein.fasta)

Second: the reference protein FASTA (reference_protein.fasta)

Keep the default settings unless the instructor tells you otherwise.

Click Run Align.

In the results, locate the positions where the sequences differ (mismatches, gaps).

Copy the alignment output (or download if available) and save it for your notes.

Copy / Paste / Save

COPY: Copy the full FASTA text from synthetic_protein.fasta and reference_protein.fasta

PASTE: Paste both into the UniProt Align input box (two FASTA entries in one box).

RUN: Click Run Align.

SAVE: Copy the alignment result into uniprot_alignment.txt. Add 1–2 sentences: what is the closest match, and which residues differ.

What to look for in the results

Are there gaps? (Often indicates an insertion/deletion relative to the reference).

Are the differences clustered (e.g., ARD region) or scattered?

Do you see any '*' stop symbols? If yes, your input may contain a stop codon or a translation issue.

?Quick sanity checks (worth 20 seconds)

SFAT fails or gives nonsense features: you probably pasted spaces/headers or picked the wrong locus/level.

Translation shows many stop codons (*): you translated genomic DNA instead of CDS, or selected the wrong frame.

BLAST hit looks short: check coverage/alignment length; you may have pasted only part of the sequence.

Did you paste FASTA headers for BOTH sequences? Each sequence must start with a line beginning with '>'.

Did you accidentally paste DNA instead of protein? Protein should not contain A/C/G/T-only patterns and should not contain long stretches of only four letters.

Are you aligning proteins from the same locus? Aligning A vs B will give nonsense.

If the alignment looks shifted: re-check for missing residues at the start (signal peptide / leader) and confirm you copied the full entry from X_prot.fasta.

Output you will reuse in Step 3

Use the alignment to update your amino-acid variant list (position + AA change). This becomes the input for surface-exposure and antibody-relevance checks in Step 3.

Save the following results:

synthetic_input_sequence.txt (DNA)

synthetic_CDS.txt (CDS)

synthetic_protein.txt (protein)

Closest supported comparator from this step, with the BLAST service, database and accession recorded

?Help me through this step

Work through it

  1. Open the SMS2 instructions and follow the symbol checks. Paste the full reference FASTA into the first box and the full synthetic FASTA into the second, replacing both examples. Run with the settings shown in the guide.
  2. Check both names and input lengths in the result. Preserve both aligned FASTA rows including gaps. Use Color Align Conservation as described in the guide to display differences. Save the rows, method, settings and your explanation in the workbook and optionally as sms_alignment.fasta.

Check your result or recover

If the result is missing, check for the SMS2 popup. If either sequence is unexpectedly short, stop and compare the submitted inputs with the originals. The UniProt route below uses a single box for both entries. If neither works, use a facilitator-approved saved result and verify the sequence pair.

!Understand what you are doing

What the result means

The alignment compares two proteins already selected. It reports columns of corresponding residues and gap characters. For a residue index in each sequence, count that row’s amino-acid letters only. Record both positions when gaps occur.

How to interpret it

A long divergent tail or multiple gaps can be an alignment representation of a single coding frameshift. Compare the nucleotide alignment and translation before counting them as separate biological events. Use the mapped positions in Step 3.
