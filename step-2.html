2.1 Clean the synthetic DNA sequence and save it

Goal: you start with a provided synthetic DNA sequence. Before analysis, make sure it contains only DNA letters (A/C/G/T) and nothing else.

What you do

Open Downloads → Practice cases. Use the assigned FASTA shown above. If you are a guest, open the Genomic DNA FASTA for the case your facilitator assigned. Copy the DNA sequence from that file.

Open Cleaned synthetic DNA input and paste the DNA sequence into the field.

Clean the sequence: remove the FASTA header and layout characters such as whitespace and line numbers. Check unexpected sequence symbols with the facilitator.

Keep only A/C/G/T.

Check that Cleaned synthetic DNA input holds only the sequence letters. Record the case in Assigned case and reference allele, then the input type in Input types and numbering. Record the exact source and number of bases in Synthetic input, annotation and translation notes.

Copy / Paste / Save

COPY: the full synthetic DNA sequence from Downloads → Practice cases.

PASTE: into Cleaned synthetic DNA input.

CLEAN: remove header and layout characters. Check unexpected sequence symbols before proceeding.

SAVE: keep the cleaned letters in Cleaned synthetic DNA input and the input details in Synthetic input, annotation and translation notes.

What you have now

One clean DNA sequence (A/C/G/T only) that you can safely paste into web tools.

Check your result or recover

Check the full length against the original after ignoring formatting. If an unexpected symbol appears, locate it in the original and ask before editing. Deleting a nucleotide can change a reading frame or shift every later coordinate.

!Understand what you are doing

What the result means

Genomic and CDS inputs can represent different exercises even under the same case number. A protein file has amino-acid letters and is for the later comparison. Use the file label and source rather than inferring sequence type from a few letters.

How to interpret it

This task prepares an input, not a result. Record the case, file name, type and length so you can reproduce the annotation and BLAST searches. Keep the assigned input details in Synthetic input, annotation and translation notes.

2.2 Convert synthetic DNA to exons/CDS (and often protein) with SFAT

Goal: analyse the synthetic DNA with SFAT so you can identify exon/intron features (if present), generate the CDS (exons stitched together), and obtain a correct protein sequence.

Tool to use

IPD-IMGT/HLA Sequence Feature Annotation Tool (SFAT).

What you do (click-by-click)

Open the Sequence Feature Annotation Tool (SFAT).

Copy the letters from Cleaned synthetic DNA input and paste into SFAT. Leave out the FASTA header and spaces.

Select the locus that matches your sequence (e.g., A, B, DRB1, MICB, etc.).

Select Level: Genomic for a genomic file with introns, or CDS for an assigned coding-only file.

Run the annotation by pressing the “Annotate Sequence Now” button.

Copy / Paste / Save

COPY: the letters from Cleaned synthetic DNA input.

PASTE: into SFAT (letters only; no header).

SELECT: locus + correct Level (Genomic or CDS).

SAVE: click CDS below the Feature Map and paste the letters under Sequence into Verified synthetic CDS if the input supports this coding sequence.

SAVE: if SFAT provides a supported translation, click Protein below the Feature Map and paste the amino-acid letters under Sequence into Verified synthetic protein sequence.

RECORD: in Synthetic input, annotation and translation notes, enter the selected locus and level, exon boundaries, codon_start and any warnings.

What to look for in the results

Exon/intron boundaries (where each exon starts/ends in your input). Note: splice changes can introduce premature stops and cause null alleles.

A coding sequence: exonic sequence stitched together (introns removed).

A codon_start / reading-frame hint (important for correct translation).

The translated protein sequence.

Record in My workbook · Verified synthetic CDS · Verified synthetic protein · Annotation notes

?Help me through this step

Work through it

  1. Copy Cleaned synthetic DNA input into SFAT. For a workshop HLA-A input select locus A. Choose Genomic for genomic input or CDS for an assigned coding input. Submit once and leave the results tab open.
  2. Paste the CDS letters into Verified synthetic CDS and any supported amino-acid sequence into Verified synthetic protein sequence. In Synthetic input, annotation and translation notes, record the submitted type, codon_start, exon boundaries if available and any warning. For CDS input, compare the original in Cleaned synthetic DNA input with what SFAT returns.

Check your result or recover

If SFAT supplies an apparently normal CDS despite a boundary warning, keep both observations. If no justified CDS is available, record that limitation and consult the facilitator. Use a supplied CDS as a fallback only when its relationship to this exact input is established. Record both the reported result and any unresolved status in Synthetic input, annotation and translation notes.

!Understand what you are doing

What the result means

SFAT predicts the expected feature layout from sequence similarity. A splice-site change may disrupt that layout biologically even when the tool reports the usual exon boundaries.

How to interpret it

Keeping the source sequence, settings and warnings separates an observed DNA change from a hypothetical protein. That distinction determines whether the alignment and accessibility tasks can be interpreted for the case.

2.3 Translate the CDS into protein (if not provided by SFAT)

Goal: ensure you end Step 2 with a correct one-letter amino-acid sequence so you can run protein-level comparisons.

Option A (preferred): take the protein directly from SFAT output

In the SFAT results, find the Protein section.

Paste the one-letter amino-acid sequence into Verified synthetic protein sequence.

Copy / Paste / Save

COPY: the one-letter amino-acid sequence from the SFAT translation output.

SAVE: paste the verified amino-acid letters into Verified synthetic protein sequence.

Option B (manual/universal): translate the CDS with ExPASy Translate

Open ExPASy Translate.

Copy the letters from Verified synthetic CDS into ExPASy Translate.

Select Compact, leave only forward checked for the coding-strand CDS, keep Standard genetic code and click TRANSLATE!. Under Results of translation, read the three forward frames. If SFAT gives codon_start, use the corresponding frame (1, 2 or 3). Check the first stop in that frame against the reference.

Paste the amino-acid letters before the first verified stop into Verified synthetic protein sequence. Paste the full selected-frame output, including stop symbols, into Synthetic input, annotation and translation notes and record the frame, first stop and protein length. If the frame or transcript is unresolved, record that there and leave the protein field empty.

Optional: paste other frames into Scratchpad with their frame numbers.

Copy / Paste / Save

COPY: the letters from Verified synthetic CDS.

PASTE: into ExPASy Translate.

CHOOSE: the correct frame (use SFAT codon_start).

SAVE: paste the verified amino-acid letters into Verified synthetic protein sequence.

Record in My workbook · Verified synthetic protein · Frame and first stop

?Help me through this step

Work through it

  1. Use Verified synthetic protein sequence if you already recorded a verified SFAT protein. Record its length in Synthetic input, annotation and translation notes. To translate with ExPASy, copy Verified synthetic CDS and use the Compact output.
  2. Use the annotated frame and codon_start from Synthetic input, annotation and translation notes. Compare the start and length with Reference protein sequence for the matching reference. In Synthetic input, annotation and translation notes, paste the full selected frame and record its first stop and residue count. Paste the supported letters before the stop into Verified synthetic protein sequence.

Check your result or recover

If you see a short product, compare its CDS codons to the reference before assuming an input error. For an unresolved splice outcome, write ‘protein product unresolved’ and use a facilitator-approved reference example for the later tool practice. Label that example separately.

!Understand what you are doing

What the result means

A correct reading frame can contain an early stop after an indel or a substitution. The other five frames are alternative readings of the same DNA and are not alternative evidence of expression.

How to interpret it

A translated sequence is a prediction from the input and frame. Neither a full-length nor a short in-silico translation establishes expression, protein stability or surface presentation.

2.4 Find the closest known allele (NIH BLAST)

Goal: determine which known allele your synthetic sequence most closely resembles, and document why it looks novel relative to that closest match (identity, coverage, mismatches).

Preferred tools to use

Basic Local Alignment Search Tool: https://blast.ncbi.nlm.nih.gov/Blast.cgi

Alternative for HLA: There are lots of different BLAST services out there to use, but these may or may not have the same library of sequences to compare against or give the same results. Why not repeat the step above using the service at the EBI, https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast? How do the results differ, why might this be?

For DNA sequences: Nucleotide -> Nucleotide BLAST

For protein sequences: Protein BLAST

What you do (Nucleotide similarity)

Open NCBI Nucleotide BLAST. Service links: https://blast.ncbi.nlm.nih.gov/Blast.cgi (https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast/nucleotide)

Your sequence contains DNA sequences, thus select the option: Nucleotide BLAST nucleotide -> nucleotide

Copy Cleaned synthetic DNA input into Enter Query Sequence. Use one input per search. Leave Align two or more sequences unchecked for the database search.

Under Choose Search Set, note the database shown (for example, core_nt). Keep the displayed database and program unless instructed otherwise. Click BLAST once and keep the results tab open.

Open Descriptions for the hit list and Alignments to inspect the matching regions. Check the active sort order, query coverage and percent identity.

Choose a same-locus comparator with adequate coverage of the region you will analyse. Document ties and check the actual alignment before deciding.

Open a hit in Alignments. Verify the HLA locus and inspect Query and Sbjct coordinates, percent identity, mismatches and gaps. Record the allele and accession when the record identifies them. Record the hit and accession in BLAST results.

Use a complete CDS hit for a coding comparison when it covers the relevant sequence. For a genomic comparison, inspect genomic hits for coverage of introns and splice boundaries. If BLAST does not return a usable hit, record the reason. With facilitator approval you can use the supplied workshop reference as an explicit comparator and record that choice. Enter the choice and reason in Chosen reference and evidence.

Identical nucleotides are connected by a “|” between your query sequence and the obtained homologous subject. For mismatches, this symbol is missing.

Copy / Paste / Save

COPY: letters from Cleaned synthetic DNA input. Check the input type in Synthetic input, annotation and translation notes.

PASTE: into NCBI Nucleotide BLAST.

RUN: note the visible database and program before clicking BLAST.

SAVE: in BLAST results, record the top three hits for each run: allele or accession, identity, alignment length, coverage, mismatches and gaps.

WRITE: one or two sentences: closest known allele + evidence + novelty evidence (differences at ...). Chosen reference and evidence

In My workbook: BLAST top hits and search settings · Chosen reference and evidence.

?Help me through this step

Work through it

  1. Open Nucleotide BLAST and paste Cleaned synthetic DNA input. Check the selected database and run. In BLAST results, identify the input type and database for each search, including any separate EBI or protein BLAST search.
  2. Read Descriptions and Alignments. In BLAST results, record the top three relevant hits, accession or allele, identity, coverage, aligned length, mismatches and gaps. Inspect coordinates and orientation. In Chosen reference and evidence, record any ties and why your chosen same-locus comparator covers the region of interest.

Check your result or recover

If a hit has 100% identity over a small region, inspect longer hits before choosing. If your genomic query aligns only to CDS, introns may be missing from that comparison. If no suitable hit or the service fails, use the facilitator’s designated comparator and record why it was used. Document your decision in Chosen reference and evidence.

!Understand what you are doing

What the result means

BLAST reports local similarity. The first row reflects the selected database, scoring and sort order. A high identity applies to the aligned segment, while coverage tells you how much of the query was represented.

How to interpret it

A difference from your chosen comparator is evidence for this exercise. Establishing novelty would require a broader database and sequence validation. Two services can legitimately return different hits.

2.5 Prepare the closest matched allele protein for alignment

Goal: retrieve the protein for the supported comparator from ANHIG/IMGTHLA and store the complete entry in Comparator protein FASTA.

What to do

Open the ANHIG/IMGTHLA repository on GitHub.

Open the fasta/ folder.

Open the protein FASTA for your locus: X_prot.fasta (where X is the gene/locus, e.g., A_prot.fasta, DRB1_prot.fasta, MICB_prot.fasta). View the raw data file. The supplied reference protein is a shortcut only if it is the allele you chose in task 2.4.

Find the allele you selected in Chosen reference and evidence in the file (use Ctrl+F or Command+F).

Copy the entire FASTA entry: the header line starting with '>' AND the amino-acid sequence lines below it.

Copy / Paste / Save

COPY: Copy the full FASTA entry for the closest matched allele from X_prot.fasta (including the '>' header).

PASTE: paste the complete record into Comparator protein FASTA.

CHECK: You should see exactly one header line starting with '>' followed by only amino-acid letters (no numbers, no spaces).

RECORD: in Chosen reference and evidence, add the protein source, allele and accession. Leave the FASTA field for the FASTA entry only.

What you have now

One complete FASTA record, header and sequence, in Comparator protein FASTA.

Record in My workbook · Comparator protein FASTA · Comparator source and accession

?Help me through this step

Work through it

  1. Use the allele and locus in Chosen reference and evidence. In ANHIG/IMGTHLA, open fasta and the locus-specific _prot.fasta file. Choose Raw, search for the allele and verify the complete designation on the header, including any expression suffix.
  2. Copy the header and all of its sequence lines up to the next > header. Paste in Comparator protein FASTA. Check for exactly one header, amino-acid letters and the expected sequence boundaries.

Check your result or recover

If the selected hit is a partial record or lacks a protein entry, ask for the closest usable comparator. Record the accession, allele, coverage and why you chose it. Check that both protein inputs represent the same locus and that you know whether both include the leader. Record the verified comparator and why you selected it in Chosen reference and evidence.

!Understand what you are doing

What the result means

The BLAST hit identifies a database record. The exact input to the alignment is the FASTA entry in Comparator protein FASTA. A truncated database record can introduce a terminal gap unrelated to your variant.

How to interpret it

Two alleles can encode identical proteins while differing at nucleotide level. A shared protein sequence does not establish G-group identity or the expression status of either allele.

2.6 Convert your SFAT protein output into FASTA format

If your protein is unresolved, record why in Synthetic input, annotation and translation notes and leave the case FASTA field empty. Use the separate demonstration in 2.7 to practise the mechanics.

Goal: add a FASTA header to your verified protein so SMS2 or UniProt can identify it. Prepare the entry in Synthetic protein FASTA.

What to do

Open Verified synthetic protein sequence to retrieve the supported amino-acid letters.

Open Synthetic protein FASTA. Use the first line for the FASTA header.

Add a FASTA header line on the first line, starting with '>' (example: >synthetic_novel_allele).

Copy the letters from Verified synthetic protein sequence and paste them on the next line of Synthetic protein FASTA.

Check the complete entry in Synthetic protein FASTA. It is saved as you type.

Copy / Paste / Save

COPY: the amino-acid letters from Verified synthetic protein sequence.

PASTE: paste the sequence into Synthetic protein FASTA on the line below a header such as >synthetic_novel_allele.

CHECK: use one header line beginning with > and amino-acid letters on subsequent lines. Keep the original translation and the recorded stop. If your file contains X or another ambiguous letter, follow the symbol guidance before submitting.

RECORD: in Synthetic input, annotation and translation notes, note how you handled stops or ambiguous residues.

What you have now

• A FASTA-formatted protein entry for your synthetic allele.

Record in My workbook · Synthetic protein FASTA · Sequence preparation notes

?Help me through this step

Work through it

  1. Copy the letters from Verified synthetic protein sequence. In Synthetic protein FASTA, type a unique header such as >synthetic_case, press Enter and paste the letters on the next line.
  2. Check that the header begins with > and that the body has letters only. Keep a record of the original length. For a confirmed stop, submit the translated segment before the stop and document that choice. For an X or another unusual letter, read the alignment input guidance before submitting.

Check your result or recover

If the protein is unresolved, leave Synthetic protein FASTA empty, record the limitation in Synthetic input, annotation and translation notes and keep any separately labelled practice result in Scratchpad.

!Understand what you are doing

What the result means

FASTA is a packaging format. Adding a header preserves the underlying protein sequence. Keep an untouched source copy and a separate prepared input so you can trace every modification.

How to interpret it

A stop marker is different from an amino acid. Deleting an internal unknown residue can shift all later positions. Record how you handled non-standard symbols before interpreting any residue number. Record how you handled each symbol in Synthetic input, annotation and translation notes.

2.7 Align the two proteins (SMS2 first choice)

Goal: generate a protein alignment between your synthetic allele protein and the closest matched allele protein, so you can see the exact amino-acid differences in context.

Use a supported protein from your case. If it is unresolved, select the HLA-B demonstration in Saved protein comparisons and practise with the two provided records. Keep this comparison separate from your case.

Option 1. SMS2 Pairwise Align Protein (recommended)

Follow the SMS2 instructions, help and screen examples · Open saved comparisons if the tool is unavailable

  1. Check your protein symbols and lengths first. SMS2 can silently remove X and other unsupported characters; follow the linked preparation guidance before proceeding.
  2. Open Pairwise Align Protein ↗. Replace the first example with your Comparator protein FASTA and the second with your Synthetic protein FASTA: one entry in each box.
  3. Use BLOSUM62, gap opening 12 and extension 2, then click Submit.
  4. Verify the reported names and lengths. Copy only the two aligned FASTA entries, preserving gaps.
  5. Follow the guide to display the alignment with Color Align Conservation and determine the residue differences.
  6. Save the alignment, settings and observations in your workbook. Use these results for Step 3; you do not need to repeat the alignment with UniProt.

SMS2 calculates in your own browser, avoiding the shared EBI queue. If it cannot handle your input, consult the facilitator; do not silently remove unknown residues.

Option 2. UniProt Align (original instructions)

Use this second option if requested by the facilitator. It uses the EBI service and may queue. The instructions below apply specifically to UniProt, including its single input box and output filename.

What to do (click-by-click)

Open UniProt Align.

In the sequence input box, paste BOTH FASTA entries, one after the other:

First: copy the complete entry from Synthetic protein FASTA.

Second: copy the complete entry from Comparator protein FASTA.

Keep the default settings unless the instructor tells you otherwise.

Click Run Align.

In the results, locate the positions where the sequences differ (mismatches, gaps).

Copy the alignment output (or download if available) and save it for your notes.

Copy / Paste / Save

COPY: both complete entries from Synthetic protein FASTA and Comparator protein FASTA.

PASTE: Paste both into the UniProt Align input box (two FASTA entries in one box).

RUN: Click Run Align.

SAVE: paste both aligned rows into Protein alignment and variant list. Add the method, settings, closest match and residues that differ.

What to look for in the results

Are there gaps? (Often indicates an insertion/deletion relative to the reference).

Are the differences clustered (e.g., ARD region) or scattered?

Do you see any '*' stop symbols? If yes, your input may contain a stop codon or a translation issue.

?Quick sanity checks (worth 20 seconds)

SFAT fails or gives nonsense features: you probably pasted spaces/headers or picked the wrong locus/level.

Translation shows many stop codons (*): you translated genomic DNA instead of CDS, or selected the wrong frame.

BLAST hit looks short: check coverage/alignment length; you may have pasted only part of the sequence.

Did you paste FASTA headers for BOTH sequences? Each sequence must start with a line beginning with '>'.

Did you accidentally paste DNA instead of protein? Protein should not contain A/C/G/T-only patterns and should not contain long stretches of only four letters.

Are you aligning proteins from the same locus? Aligning A vs B will give nonsense.

If the alignment looks shifted: re-check for missing residues at the start (signal peptide / leader) and confirm you copied the full entry from X_prot.fasta.

Prepare for Step 3

Paste the aligned rows into Protein alignment and variant list. In Input types and numbering, note whether the input proteins include the signal peptide. You will use this numbering for exposure and recognition checks.

?Help me through this step

Work through it

  1. Open the SMS2 instructions and follow the symbol checks. Paste the full entry from Comparator protein FASTA into the first box and the full entry from Synthetic protein FASTA into the second, replacing both examples. Run with the settings shown in the guide.
  2. Check both names and input lengths in the result. Preserve both aligned FASTA rows including gaps. Use Color Align Conservation to display differences. Paste both rows in Protein alignment and variant list, then add the method, settings and your explanation.

Check your result or recover

!Understand what you are doing

What the result means

The alignment compares two proteins already selected. It reports columns of corresponding residues and gap characters. For a residue index in each sequence, count that row’s amino-acid letters only. Record both positions when gaps occur. Keep the two position columns in Protein alignment and variant list.

How to interpret it

A long divergent tail or multiple gaps can be an alignment representation of a single coding frameshift. Compare the nucleotide alignment and translation before counting them as separate biological events. Use the mapped positions in Step 3.
