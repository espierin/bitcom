1.1 Download the genomic DNA sequence (FASTA)

Goal: start with the full genomic sequence (exons + introns) copied from a FASTA file.

What you do

Open the ANHIG/IMGTHLA repository in your browser (GitHub).

Go to the fasta/ folder and open the genomic FASTA file for your locus.

Genomic files typically follow this naming: X_gen.fasta where X = locus/gene (e.g., A_gen.fasta, DRB1_gen.fasta, MICB_gen.fasta).

To see the content of the file, press “View raw”. Alternatively, press the Raw button, copy raw file button, or download button on the right.

Find your allele entry in the file: use Ctrl+F and search for the allele name (e.g., A*01:01:01:01).

Understand the FASTA layout: one header line starting with '>' (identifier + allele name + sometimes length/metadata), followed by the DNA sequence on the next lines (until the next entry or the end of the file).

Copy the sequence letters only (A/C/G/T). DO NOT copy the header line that starts with '>'.

Open Notepad (or similar) as your scratchpad.

Save what you copied as your_allele_genomic.txt.

Copy / Paste / Save

COPY: DNA letters only (A/C/G/T) from the FASTA entry.

DO NOT COPY: the header line starting with '>' (gene/allele metadata).

PASTE: into Notepad first (scratchpad).

SAVE: as your_allele_genomic.txt

What you have now

One long genomic DNA sequence (exons + introns) for one allele saved in a local txt file

?Practical help

Use a plain-text editor. In TextEdit choose Format → Make Plain Text. Keep the FASTA record together and stop copying at the next header.

1.2 Convert genomic DNA to coding DNA sequences with the Sequence Feature Annotation Tool

Goal: The Sequence Feature Annotation Tool (SFAT) identifies exon/intron features and outputs the coding sequence (CDS), which is the exonic sequence with introns removed.

Tool to use

IPD-IMGT/HLA Sequence Feature Annotation Tool (SFAT).

What you do (click-by-click)

Open the Sequence Feature Annotation Tool page.

Paste your genomic DNA letters only (no FASTA header, no spaces).

Select the locus that matches your sequence (e.g., A, B, DRB1, MICB, etc.).

Select Level: Genomic (because your input includes both the exons and the introns).

Run the annotation by pressing the “Annotate Sequence Now” button.

Copy / Paste / Save

COPY: the full content of your_allele_genomic.txt

PASTE: into SFAT (letters only; no header).

SELECT: correct locus and Level = Genomic.

SAVE: copy the CDS output into your_allele_CDS.txt

WRITE DOWN: exon/intron boundaries and codon_start (if shown).

What to look for in the results

Exon/intron boundaries (where each exon starts/ends in your input).

A coding sequence (CDS): exonic sequence stitched together (introns removed).

A codon_start / reading frame hint (important for correct translation).

?Practical help

The locus dropdown uses A, B and other gene names. Choose the level that matches your input. If SFAT fails, use the corresponding supplied CDS and protein from Downloads.

In the SFAT results, find the Protein sequence in the “Protein” tab or at the bottom or in the GenBank/ENA/IMGT/HLA section.

Copy the one-letter amino-acid sequence into your_allele_protein.txt.

Copy / Paste / Save

COPY: the one-letter amino-acid sequence from the SFAT protein/translation output.

Option B (manual/universal): translate the CDS with ExPASy Translate

Open ExPASy Translate (https://web.expasy.org/translate/).

Paste the CDS (from your_allele_CDS.txt) — NOT the genomic sequence.

Choose an output format (default is Compact: M, -, no spaces).

Press the “TRANSLATE!” button.

By default ExPASy shows 6 possible frames (3 forward, 3 reverse).

If SFAT provides codon_start, use it to select the correct forward frame: start=1 (in SFAT) -> frame 1 (in ExPASy); start=2 (in SFAT) -> frame 2 (in ExPASy); start=3 (SFAT)-> frame 3 (in ExPASy).

Copy the relevant protein sequence into your_allele_protein.txt.

Optional: ExPASy can download all frames as one text file.

Copy / Paste / Save

COPY: the full content of your_allele_CDS.txt

PASTE: into ExPASy Translate (not genomic DNA).

CHOOSE: the correct frame (use SFAT codon_start if available).

SAVE: as your_allele_protein.txt

?Quick sanity checks (20 seconds)

Did you accidentally paste the FASTA header (>...)? SFAT expects sequence letters only.

Did you translate genomic DNA instead of CDS? That often creates many stop codons (*) because introns break the reading frame.

Do you have a codon_start from SFAT? Use it; it prevents frame mistakes.

2.4 Find the closest known allele (NIH BLAST)

Goal: determine which known allele your synthetic sequence most closely resembles, and document why it looks novel relative to that closest match (identity, coverage, mismatches).

Preferred tools to use

Basic Local Alignment Search Tool: https://blast.ncbi.nlm.nih.gov/Blast.cgi

Alternative for HLA: There are lots of different BLAST services out there to use, but these may or may not have the same library of sequences to compare against or give the same results. Why not repeat the step above using the service at the EBI, https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast? How do the results differ, why might this be?

For DNA sequences: Nucleotide -> Nucleotide BLAST

For protein sequences: Protein BLAST

What you do (Nucleotide similarity)

Go to the BLAST website: https://blast.ncbi.nlm.nih.gov/Blast.cgi (https://www.ebi.ac.uk/jdispatcher/sss/ncbiblast/nucleotide)

Your sequence contains DNA sequences, thus select the option: Nucleotide BLAST nucleotide -> nucleotide

Enter your Query Sequence in the text box.

Press the blue BLAST button on the lower left of the page and wait.

The output contains a list of sequences that are (partially) identical to your sequence, sorted by percent identity.

The closest matching HLA variant is on the top of that list.

You can inspect the homology in an alignment by clicking on the description.

It may make sense to select the one that has been described as “Complete CDS”.

Identical nucleotides are connected by a “|” between your query sequence and the obtained homologous subject. For mismatches, this symbol is missing.

Copy / Paste / Save

COPY: sequence from the appropriate file (genomic).

PASTE: into the matching NIH BLAST page.

RUN: keep defaults unless instructed otherwise.

SAVE: in closest_match_notes.txt record the top 3 hits for each run: allele name, % identity, alignment length/coverage, mismatches/gaps.

WRITE: 1–2 sentences: closest known allele + evidence + novelty evidence (differences at ...).

?Practical help

Inspect query coverage, identity, gaps and the alignment together when selecting the closest match. Record the database used.

3.1 Is this variation leading to a premature end of the protein?

3.1.1 Stop codon introduced by the variant

Goal: check if the variant introduces an early stop (truncation).

What you do

Open synthetic_protein.txt.

Look for an early stop sign (some tools show '*' as stop) or an unexpectedly short protein.

Cross-check with NCBI ORFfinder (fast sanity check).

Copy / Paste / Save

COPY: synthetic_CDS.txt (preferred) or synthetic_input_sequence.txt (if CDS not available).

PASTE: into ORFfinder and run.

LOOK FOR: the longest ORF; whether it stops much earlier than expected; whether multiple ORFs appear because of early stops.

SAVE: write a 3–5 line conclusion in step3_truncation_check.txt: 'Stop codon present: yes/no' + evidence (protein has */ORF ends at ...).

?Practical help

If ORFfinder is unavailable, translate the CDS with ExPASy in the annotated frame. Compact output uses a dash for a stop. Compare the annotated reading frame as well as the longest ORF.

3.1.2 Frameshift (insertion/deletion not divisible by 3)

Goal: check whether an indel causes a frameshift and therefore likely truncation.

What you do

From your coding alignment, identify insertions/deletions in the coding sequence.

Check the length: 3, 6, 9... bases -> in-frame; 1, 2, 4, 5... bases -> frameshift.

Confirm with ORFfinder: a frameshift often creates a short, abnormal ORF.

Copy / Paste / Save

COPY: the exact indel from your alignment (length and position).

WRITE: in step3_truncation_check.txt add: 'Frameshift: yes/no', 'Indel length: ... bp', 'Expected consequence: early stop likely / not likely'.

3.1.3 Alternative splicing / splice site disruption (genomic sequences)

This only applies if your synthetic sequence includes introns (genomic input).

What you do (simple, manual but effective)

Run SFAT on the genomic sequence and record exon boundaries.

Check whether your variant sits at an exon boundary:

- Donor site (start of intron): usually GT right after the exon

- Acceptor site (end of intron): usually AG right before the next exon

If your variant changes those canonical bases, splicing disruption is plausible.

Optional (stronger): SpliceAI Lookup

If you can express your change as a variant on a reference genome coordinate, use SpliceAI Lookup and record the delta score.

Copy / Paste / Save

WRITE: in step3_truncation_check.txt add: 'Splice-site hit: yes/no', 'Which boundary: exon X donor/acceptor', 'Reason: canonical GT/AG changed / nearby splice motif changed'.

OPTIONAL: add 'SpliceAI delta score' if used.

3.2 Does this change the Antigen Recognition Domain (ARD; and therefore G/P grouping logic)?

ARD definition used here

Class I: peptide-binding domain is encoded by exons 2 and 3.

Class II: peptide-binding domain is encoded by exon 2.

3.2.1 Does this lead to another G-group characterization?

Goal: determine whether the ARD nucleotide sequence differs from the closest allele (relative G-group statement).

What you do

Using SFAT output, isolate the ARD nucleotide sequence:

- Class I: exon 2 + exon 3

- Class II: exon 2

Compare that ARD nucleotide sequence to the closest allele’s ARD nucleotide sequence (IPD alignment tool can show exon-level alignments).

If any nucleotide differs in the ARD region, it is not the same G-group as the closest allele (relative statement).

Copy / Paste / Save

COPY: ARD exon nucleotide sequence(s) from SFAT + closest allele ARD exon sequence(s).

COMPARE: identical yes/no.

SAVE: in step3_ard_check.txt write: 'ARD nucleotide change: yes/no' and 'Same G-group as closest allele? yes/no (relative)'.

3.2.2 Does this lead to another P-group characterization?

Goal: determine whether the ARD protein sequence differs from the closest allele (relative P-group statement).

What you do

Translate the ARD region (or use your protein alignment) and check whether any AA in the ARD differs.

Any ARD amino-acid difference vs closest allele implies a different P-group (relative statement).

Copy / Paste / Save

COPY: your ARD AA changes from step3_variant_list.txt.

DECIDE: are any within ARD? (Class I: exons 2+3; Class II: exon 2).

SAVE: in step3_ard_check.txt write: 'ARD protein change: yes/no' and 'Same P-group as closest allele? yes/no (relative)'.

3.2.3 Does this alter the peptide repertoire (binding groove)?

You do not prove this here — you flag plausibility.

What you do (workshop rule)

If the change is in ARD, it may affect peptide repertoire.

Strengthen your conclusion using structure (Step 3.3 + optional PyMOL): if the mutated residue points into the binding groove or sits close to the peptide, plausibility increases.

Copy / Paste / Save

WRITE: in step3_ard_check.txt: 'Peptide repertoire impact plausible: low / medium / high'.

WRITE: reason: 'ARD change yes/no; residue points to groove yes/no'.

3.3.4 Could this lead to antibody recognition in general?

Goal: do a useful screen without overclaiming specific antibody specificities.

What you do (workshop-level decision rule)
