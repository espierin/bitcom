Hands-on HLA Sequence Analysis

Critical checks by task

Step 1 · Genomic DNA, annotation and protein

See before moving on. One genomic FASTA record, the locus and input level used in SFAT, the annotated CDS or a documented matching fallback, and the resulting protein or a recorded limitation. The workbook should distinguish sequence lengths in bases and residues.

  • For “sequence rejected” or an implausible annotation, check for a pasted header in a letters-only field, a second FASTA record, copied line numbers, or a genomic file selected as CDS. Check locus A for the workshop HLA-A cases.
  • If the translation is unexpectedly short, inspect the annotated frame and first stop. Repeat the translation from the verified CDS where appropriate. A longer ORF in another frame is insufficient evidence that the annotated frame is wrong.
  • If SFAT is unavailable, use the packaged CDS and protein only when they correspond to the exact assigned input. Document when the file is a provided result. Independent CDS and genomic exercises must remain separate.

Step 2 · Comparator and alignment

See before moving on. Input identity, a supported reference choice, and either two aligned rows with traceable lengths or an explicit unresolved-protein note. Record the database or tool and any difference between the selected BLAST hit and the workshop reference.

  • Check sequence type, database, identity and query coverage together. A high percentage over a short region cannot justify a full-length comparator. Compare relevant tied hits and record uncertainty.
  • Use SMS2 first. Put one complete FASTA entry in each box, confirm the two input lengths, and open the results window. The workshop settings are BLOSUM62, gap opening 12 and extension 2. If a pop-up is blocked or the page does not load, open the saved pair.
  • Watch for silent filtering of X and other symbols. For the archived Case 05 short protein, the saved alignment covers the known prefix. Its exact NetSurfP input still contains the terminal X. A confirmed stop marker in Case 04 is treated according to its preparation note.
  • Count residue letters in each row separately. Gaps do not advance that row’s sequence number. An unaligned terminal tail after a stop or frameshift does not imply a separate deletion at every column.

Step 3 · Coding consequences and immune interpretation

See before moving on. The variant list includes coordinates and reference/variant letters, the correct distinction between observed DNA evidence and predicted product, and a result or limitation for each applicable interpretation task.

  • Separate early stop, coding frameshift and possible splice disruption. A standard SFAT annotation can report conventional exons even when a splice-site change makes the transcript uncertain. Report unresolved protein rather than attaching a protein prediction to the wrong input.
  • For class I HLA-A, compare coding exons 2 and 3 for ARD nucleotide and protein evidence. Keep G-group nucleotide identity, P-group protein identity and official membership separate. The presence of a translated sequence does not establish expression.
  • Before RSA lookup, check the exact archived sequence, the entered precursor position and its amino-acid letter. If comparing with a reference, use its separately mapped position. A 24-residue shift is valid only after confirming the leader in the actual sequence being used.
  • Record numeric RSA, model version and input alongside an interpretation. Around the workshop threshold of 0.25, retain the number and the uncertainty. An RSA prediction describes solvent exposure under the model and does not establish antibody, NK or T-cell recognition.
  • For Bw4/Bw6, check the window from mature residue 77 to 83 and the locus/allotype context. Keep the peptide groove, potential epitope and receptor hypotheses separate. Treat structure and eplet checks as evidence with limits.

Step 4 · Structure mapping

See before moving on. One defensible mapping from the chosen precursor and mature numbering to the PDB ID, heavy chain and displayed residue. Check the residue letter and flanking sequence before selecting the site.

  • Distinguish the manual’s A*02:01 teaching template from an A*01 comparator. Label any homologous template. For the core case, 3BO8 gives an A*01 reference site, with chain A His 188 available for inspection.
  • In Mol*, check the correct chain instance and select at residue level. If the number exists but the residue or neighbour disagrees, recheck the mapping. If the region lacks coordinates, record it as unmapped.
  • Keep the peptide and beta2-microglobulin visible where they affect interpretation. When observing a coloured site, distinguish the modelled reference residue, a surface estimate and the hypothesised variant effect.
  • If the viewer fails, use the relevant screen example to practise identifying the chain and selection controls. Record the intended mapping and any model-dependent assessment as unresolved.

Case notes for facilitators

Use these to diagnose an input or interpretation problem after the learner has made an attempt. The saved HLA-A comparisons use the workshop A*01:01:01:01 reference. An independently chosen reference can lead to a different comparison.

Case 01 · Core substitution and numbering check

The verified HLA-A precursor inputs are 365 residues. The relevant comparison is H212L in precursor numbering and H188L in mature numbering, after confirming the 24-residue leader. The change is in exon 4, outside the class I ARD. For the exact archived input pair, RSA is about 0.331 for H and 0.360 for L. Both exceed the workshop threshold. Use 3BO8 chain A His 188 as the reference structural check. No antibody result follows from the accessibility estimate.

Case 02 · Genomic and independent CDS routes

The genomic file changes the acceptor immediately before exon 2 from AG to AA. Its resulting protein remains unresolved. The separate CDS file has a one-base insertion and a first stop at codon 31. The 30-residue archived prediction applies to that exact CDS-derived translation. If a learner moves the CDS prediction onto the genomic file, ask them to state the source of each piece of evidence again.

Case 03 · Exon 3 acceptor and unresolved translation

The genomic variant changes the acceptor immediately before exon 3 from AG to AT. SFAT can return the conventional annotated CDS. Record the splice-site evidence and uncertainty about the actual transcript. Use the HLA-B demonstration to practise the protein steps and keep its results labelled separately.

Case 04 · Coding insertion, stop and terminal marker

A one-base insertion in the supplied coding comparison shifts the frame and produces a first stop at codon 220, after 219 amino acids. The 660-base coding span includes the stop. Verify the terminal marker against the CDS and use the archived 219-residue input for alignment and NetSurfP. The supplied record is an A*01:04:01:01N example. Check published group membership separately from expression.

Case 05 · Keep the short protein and CDS separate

The provided CDS is identical to the workshop reference CDS, while the supplied short protein is a different record and ends in an unresolved X. The saved short alignment uses the known prefix. Its NetSurfP record requires the exact short input including X. The full CDS translation is a separate archive choice. Neither record establishes that the null allele produces an expressed protein.

Case 06 · ARD differences and official grouping

The supplied protein differs at precursor F33S and R41S, which are in the ARD. Use the provided genomic and protein files. The original item labelled as CDS contained protein, so derive the CDS from genomic annotation when needed. IPD-IMGT/HLA 3.66.0 lists A*01:02:01G and A*01:02P for A*01:02:01:01, different from the workshop reference groups. The expected-outcomes note about a shared G group was corrected in the workshop.

If the assigned case cannot support a protein comparison, have the learner record why and complete the mechanics on a labelled demonstration. The HLA-B pair supports alignment practice and a separate HLA-B prediction supports RSA lookup. Use the Case 01 pair as a separate exercise if a comparison of RSA values at matched reference and variant positions is needed.

Optional email sign-in and saving

  • At entry. Invite sign-in for people who want to resume on another device. The workshop remains usable as a guest. Confirm that the participant opens the latest mail link within 20 minutes, enters the receiving address again and chooses Confirm sign-in. Use the 30-day option only on the participant’s own device.
  • Mail delayed or missing. Check the typed address and spam folder. “Request accepted” indicates the relay accepted the send. A previous live test arrived after a delay. Continue as a guest while waiting and avoid repeated requests. Keep the participant’s email and confirmation link off shared screens and out of support logs.
  • Moving from guest to sign-in. Ask them to export a JSON backup first. During confirmation, the copy option can bring guest work into empty server sections. If there is existing work on the server, retain both copies and reconcile with the participant. Restoring a backup can replace the currently open work.
  • Before closing. Guests open My workbook and choose Download backup (.json). Signed-in learners wait for Saved on the server or click Save on server now. If the sync is pending or fails, download JSON. A text report or PDF is readable but cannot restore the workbook.
  • Conflicting server copy. Export the local version first. Discuss which copy to use before selecting Load server copy. Do not repeatedly save over an unresolved conflict. Confirm the same browser profile and address when continuing.
  • Locked page. Check the saved-progress panel for the first unfinished task. Open that task and ask what evidence or limitation was recorded. An optional or inapplicable task can be marked complete once the participant has documented why. A missing browser record can be recovered by signing in to the correct account or restoring their own JSON backup.
  • Shared laptop. Have the participant keep their backup, verify the server-save message if applicable, then sign out. Keep FASTA downloads and structure images separately from the JSON backup.

Escalation and handover

Give the lead a short, actionable report

Record the time, task number, case/input type, affected tool, visible error, how many desks are affected and which fallback is working. Add a public tool job ID only if useful and appropriate. Use a case label or desk number. Keep participant addresses, workbook content and confirmation links out of group messages.

Suggested room announcement: “Please keep your current job open. We’re switching to the saved result now. Choose your exact input, check the reference and record the archived source with your observation.”

Check the handoff at the end of each block

  1. Ask the learner to show the named input, one traceable observation and one uncertainty.
  2. Check that their work is saved or backed up, that they know the next unfinished task, and that any downloaded inputs and screenshots remain in their workshop folder.
  3. Share outstanding issues with the lead in aggregate. Note which fallback kept the learning goal achievable and which steps need follow-up.
